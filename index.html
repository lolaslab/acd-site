Bringing accessibility support data to developer tools

Accessibility support data has always lived apart from browser compatibility data, so developers can't easily see where a feature has gaps: in the browser, the screen reader, or both. ACD brings that data to the places developers already check for browser support. We're working with Mozilla, BCD, ARIA-AT and Baseline so developers can build accessibility-supported experiences from the start.

Our roadmap

ACD is in early development, and we're looking for funding to bring it to life.

  1. Expand test coverage We're adding browser and screen reader tests for more web features, contributing to two established test suites: Web Platform Tests (WPT) and ARIA-AT. To start we're focusing on HTML web features in Chrome, Edge, Firefox and Safari, with JAWS, NVDA and VoiceOver.
  2. Compute a support status The ACD collector will combine WPT and ARIA-AT results into an accessibility support status for each feature, published as machine-readable data.
  3. Bring it to developer tools ACD data can then be integrated into the tools developers already use to check browser support, such as MDN and Baseline.
