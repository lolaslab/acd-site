Bringing accessibility support data to developer tools.

For a long time accessibility support data has been separated from web feature support data, making it difficult for web developers to know which web features have accessibility gaps in either the screen reader, browser, or both. ACD aims to surface this data where developers already look for web feature support. We're working with Mozilla, BCD, ARIA-AT, and Baseline so developers can build accessibility-supported experiences from the start.

To start we're focussing on HTML-AAM web features, on four popular desktop browsers (Chrome, Safari, Firefox, Edge), across three screen readers (Jaws, VoiceOver, NVDA). We will expand to include more web features and assistive technologies.

  1. Lay the groundwork.

    Accessibility tests already exist, but they were designed to be read by people rather than pulled into other tools. Getting them ready for that comes first, because everything else builds on it.

  2. Broaden the coverage.

    Not every web feature has been tested yet, so the next step is extending the tests to cover more of them.

  3. Get the data to developers.

    Turn the results into a clear answer about whether a feature is accessibility-supported, and publish it in the places developers already check for browser support.
